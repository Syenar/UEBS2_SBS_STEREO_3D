Create a non-destructive UEBS2 runtime mod. Phase 1 targets side-by-side stereo output for a 3D projector. VR is a separate later phase.

Plan
1. Back up only the files we add; do not edit UEBS2.exe, Assembly-CSharp.dll, UnityPlayer.dll, or boot.config.
2. Install a Unity Mono runtime loader (BepInEx) beside the game, with an easy removal path.
3. Create a small plugin that logs the active Unity Camera and the active camera-controller type when a battle loads.
4. Test the plugin on a small battle and confirm it survives menu, free-camera, and first/third-person camera changes.
5. Clone the active camera for a second eye. Keep the original as the left eye and offset the second camera slightly to the right.
6. Render left/right views side-by-side with adjustable eye separation, convergence, FOV, and a hotkey to enable/disable stereo.
7. Test a small battle on the 3D projector. Confirm correct depth, no doubled UI, no severe shadow/LOD artifacts, and acceptable frame time.
8. Test progressively larger battles. Set a practical stereo unit-count/performance limit.
9. Only if projector stereo is stable, research a separate OpenXR/SteamVR layer for headset output, head tracking, VR UI, and controller input.

Success criteria for Phase 1
- No permanent game-file modifications.
- A small battle displays correct left/right side-by-side stereo.
- Camera modes continue to work.
- The projector can show stable 3D depth.
- Disabling the plugin immediately restores normal UEBS2 rendering.

Risks
- Stereo roughly increases scene-rendering cost and may make giant battles impractical.
- UEBS2 may replace cameras during scenes/modes, requiring reattachment.
- HUD/UI may require a separate flat overlay solution.
- Full VR is significantly harder than projector stereo and is not guaranteed by Phase 1.

Recommendation
Start with the runtime-plugin camera discovery test, then build the small-battle side-by-side stereo prototype. Do not attempt full VR until the projector test is proven.
